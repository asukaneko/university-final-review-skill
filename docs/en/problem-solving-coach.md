# Discipline-Specific Problem-Solving / Analysis Coach

When courses require more than memorization — calculations, proofs, experiment analysis, legal case analysis, clinical reasoning, data interpretation, essay writing, design critique, or other discipline-specific problem-solving skills — use this module.

## Purpose

This module extends the original "calculation/algorithm" workflow into a cross-disciplinary problem-solving framework. First determine the course's discipline category, then select the corresponding analysis template.

## General output structure

Each problem type should include:

1. Problem type name
2. Applicable disciplines and exam scenarios
3. Required concepts, rules, formulas, methods, or frameworks
4. Step-by-step problem-solving or analysis process
5. Example problem or case
6. Common variations
7. Common errors
8. Quick exam judgment method
9. Practice problems
10. Detailed answers or reference outlines

## Discipline-specific templates

### STEM / Engineering

For calculations, derivations, proofs, algorithms, code reading, system design, and experiment analysis.

**Problem-solving framework**:

1. Restate input, output, constraints, and edge cases.
2. Choose data structure or engineering model, justify choice.
3. Present algorithm or process steps.
4. Prove correctness: invariants, termination, or engineering rationale.
5. Analyze complexity, resource usage, limitations.
6. Test with normal, boundary, and failure cases.

**Algorithm sub-template**:

1. Understand the problem: input scale, data types, time limits.
2. Brute force solution: write the simplest solution first, analyze complexity.
3. Optimization ideas: can better data structures or algorithms be used?
4. Coding implementation: write clear pseudocode or code.
5. Test verification: verify correctness with concrete examples.
6. Complexity analysis: time + space complexity.

**System design sub-template**:

1. Requirements analysis: functional + non-functional requirements.
2. High-level architecture: main components and their responsibilities.
3. Data model: database schema, indexing strategy.
4. Core flow: execution path for key use cases.
5. Tradeoff analysis: why this solution, what is sacrificed.
6. Scalability considerations: how to handle growth.

**Experiment analysis sub-template**:

1. Experiment purpose: what hypothesis to verify.
2. Experimental design: variables, control group, measurement methods.
3. Data interpretation: charts, trends, anomalies.
4. Conclusion: what the data supports.
5. Error analysis: possible error sources and improvements.

### Natural Sciences / Mathematics

For theorem proofs, formula derivations, mechanism explanation, graph interpretation, and experiment analysis.

**Quantitative science problem framework**:

1. Identify phenomenon, system, and model.
2. List knowns, unknowns, units, assumptions, constants.
3. Choose equation and justify applicability.
4. Solve symbolically first if possible.
5. Track units and significant figures.
6. Interpret result in physical/biological/chemical terms.

**Proof / Theorem problem framework**:

1. State clearly what is to be proved.
2. List definitions, assumptions, available theorems.
3. Choose strategy: direct, contradiction, induction, construction, counterexample.
4. Write reason for each step, not just algebraic manipulation.
5. Check boundary cases and conclusion.

**Experiment / Data problem framework**:

1. Question: what scientific question to answer.
2. Hypothesis: prediction based on existing knowledge.
3. Variables/Controls: independent, dependent, controlled.
4. Method: experimental steps and measurement tools.
5. Data pattern: what trends the chart shows.
6. Conclusion: does the data support the hypothesis.
7. Limitations: shortcomings and improvement directions.

### Medicine / Health

For case analysis, disease mechanisms, drug reasoning, nursing decisions, public health indicators, and prevention strategies.

**Clinical reasoning framework**:

1. Presentation: chief complaint, history, key findings.
2. Key findings: positive signs, negative signs, red flags.
3. Differential diagnosis: list possible diagnoses, rank by likelihood.
4. Most likely explanation: diagnosis that best fits all findings.
5. Tests: what tests to confirm or exclude.
6. Priorities: treatment priority order.
7. Safety/Red flags: dangerous situations requiring immediate action.
8. Patient-friendly explanation: explain in plain language.

**Disease mechanism problem framework**:

1. Risk factors → Etiology → Pathogenesis → Pathological changes → Clinical manifestations → Complications.
2. Explain causality at each step.
3. Mark exam-relevant points.

**Drug reasoning problem framework**:

1. Drug class → Mechanism → Indications → Contraindications → Adverse reactions → Monitoring → Patient education.
2. Compare similar drugs.
3. Note drug interactions.

**Public Health / Epidemiology problem framework**:

1. Population → Exposure/Intervention → Outcome → Indicators → Bias/Confounding → Interpretation → Policy implications.
2. Calculate incidence, prevalence, risk ratio, odds ratio when relevant.
3. Evaluate research design validity and limitations.

### Law

For case problems, case summaries, institutional comparison, and rule application.

**IRAC / CRAC template**:

For each issue:

1. **Issue**: Frame the legal issue as a question.
2. **Rule**: State the rule, elements, and authoritative source.
3. **Application**: Apply each element to the specific facts.
4. **Conclusion**: Reach a qualified conclusion.
5. Address opposing views and uncertain facts.
6. When relevant, state remedies, defenses, or consequences.

**Essay template**:

Use: **Central thesis → Legal framework → Authority → Analysis → Rebuttal → Evaluation → Conclusion**.

Good legal essays evaluate rules for policy, coherence, fairness, efficiency, rights protection, institutional capacity, and reform implications.

### Humanities

For essays, text interpretation, historical explanation, and comparison.

**Close reading framework**:

Use: **Observation → Evidence → Technique/Form → Meaning → Context → Relevance to thesis**.

**History problem framework**:

Use: **Thesis → Timeline/Context → Causes → Evidence → Consequences → Historiographical debate → Judgment**.

**Philosophy problem framework**:

Use: **Thesis → Argument reconstruction → Assumptions → Rebuttals → Responses → Evaluation**.

### Social Sciences

For theory application, research methods, case analysis, policy analysis, and data interpretation.

**Theory application framework**:

Use: **Phenomenon → Relevant theory → Key concepts → Evidence/Case → Explanation → Limitations → Alternative theories**.

**Research methods framework**:

Use: **Research question → Hypothesis → Variables → Design → Sample → Measurement → Ethics → Validity threats → Interpretation**.

**Policy / Case analysis framework**:

Use: **Problem → Stakeholders → Causes → Evidence → Options → Tradeoffs → Recommendations → Evaluation metrics**.

### Business / Economics

For model application, financial calculations, accounting entries, graph analysis, and case decisions.

**Quantitative business/economics framework**:

1. Identify decision problem or model.
2. List data, assumptions, time horizon, units/currency.
3. Apply formulas step by step.
4. Interpret results: what they mean for the decision.
5. Sensitivity or limitation analysis.
6. If asked, provide recommendations.

**Case analysis framework**:

Use: **Situation → Problem → Evidence → Framework → Options → Evaluation criteria → Recommendations → Execution risks**.

**Economic graph framework**:

Use: **Initial equilibrium → Shock/Change → Curve shift → New equilibrium → Welfare/distributional impact → Policy implications**.

### Education / Arts / Design

For lesson plan analysis, teaching theory application, work critique, design critique, portfolio reflection, and creative process explanation.

**Lesson plan analysis framework**:

Use: **Learners/Context → Learning objectives → Activities → Assessment → Differentiation → Rationale → Evidence of learning → Improvement**.

**Design / Art critique framework**:

Use: **Intent → Context/Audience → Formal elements → Technique/Materials → Experience/Function → Evidence → Judgment → Revision direction**.

**Reflection writing framework**:

Use: **Experience → Evidence → Interpretation → Theory connection → What changed → Next steps**.

## Output principles

Do not force all courses into a calculation or algorithm format. Select the most appropriate reasoning structure based on the discipline and exam tasks.

## Cross-disciplinary comprehensive problems

When a problem involves multiple disciplines:

1. Identify the primary discipline framework.
2. Mark parts requiring cross-disciplinary knowledge.
3. Use the primary discipline's template as base, supplement with other perspectives.
4. In the answer, explain cross-disciplinary connections.

## Practice problem design principles

Good practice problems should:

1. Have clear learning objectives.
2. Include concrete facts or data.
3. Have reasonable difficulty progression.
4. Include clear scoring criteria.
5. Include common error warnings.
6. Include answer explanations and review suggestions.
