# Evidence-Based Study Strategies

Use this guide as a cross-disciplinary layer when generating any final-review package. The goal is to avoid passive summaries and convert materials into retrieval, practice, transfer, and exam-performance tools.

## Core principles

### 1. Active recall

Do not only reread notes. Convert every chapter into prompts that force retrieval:

- blank-page summaries;
- closed-book concept maps;
- flashcards with examples and non-examples;
- oral explanations using the Feynman technique;
- short-answer questions before showing the answer.

### 2. Spaced repetition

Schedule reviews across time instead of cramming:

- same day: reconstruct the chapter outline;
- next day: answer key questions without notes;
- 3-4 days later: solve mixed practice;
- 1 week later: complete a timed mini-test;
- final sprint: focus on weak points and high-yield templates.

### 3. Practice testing

Practice should resemble the exam:

- timed conditions;
- mixed topics;
- no notes during first attempt;
- answer key with rubric;
- error log after marking.

### 4. Worked examples and fading

For problem-heavy courses, start with fully worked examples, then gradually remove support:

1. study a complete solution;
2. explain each step;
3. solve a similar problem with hints;
4. solve without hints;
5. solve a transfer problem with changed surface features.

### 5. Interleaving and transfer

Mix similar topics so the student must choose the method, not just repeat a pattern. Use contrast sets such as:

- similar formulas with different assumptions;
- similar legal doctrines with different elements;
- similar diseases with different red flags;
- similar theories with different mechanisms;
- similar business frameworks with different decision purposes.

## Output requirements

Every complete review package should include:

- retrieval prompts for each chapter;
- a spaced final-week review schedule;
- a mixed practice test;
- an error-log template;
- worked examples or model answers;
- transfer questions that require applying knowledge to unfamiliar cases.

## Error log template

| Question | Error type | Why it happened | Correct rule/process | Prevention cue |
| --- | --- | --- | --- | --- |
| Q1 | Concept / calculation / application / reading | Misread condition | Use theorem only when... | Check assumptions first |

## Final-week rhythm

- **Day 7-5**: rebuild notes from memory and repair gaps.
- **Day 4-3**: mixed practice and worked-example fading.
- **Day 2**: timed mock exam and error-log review.
- **Day 1**: formula/rule/evidence sheets, light recall, no heavy new learning.
