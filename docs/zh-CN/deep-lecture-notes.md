# 深度讲义生成

这个模块用于把 PPT、讲义、教材片段、课堂截图、作业题、往年题或用户明确提到的课程资料转换成适合期末复习的详细讲义，而不是简单摘要或通用教材式概述。

## 总原则：讲义必须绑定资料

生成讲义时必须优先依据用户上传或明确提到的资料。不要只按学科常识写泛泛而谈的内容；每一章、每一节、每个重点概念都应能看出它来自哪类资料线索，例如 PPT 标题、课件小节、图示、表格、公式、例题、作业题、往年题、老师强调的关键词或用户指定的范围。

资料中没有但为了理解必须补充的内容，可以加入，但必须标注为 `补充背景知识`，不能伪装成上传资料原文。

## 每章输出结构

每一章建议包含：

1. 本章在整门课中的地位
2. 资料覆盖清单：本章对应的文件、页码/幻灯片范围、标题、图表、例题、作业题或用户提到的资料点
3. 本章核心内容
4. PPT / 讲义 / 教材片段中的重要定义
5. 关键原理、流程、公式、模型、算法、结构图、实验步骤或案例解释
6. 面向考试的讲解
7. 常见题型
8. 易错点
9. 概念对比表
10. 一页速记版

## 单元内容密度要求

不要把一个单元压缩成几条抽象结论。只要资料中某个单元有实质内容，就必须展开到可复习、可背诵、可做题的程度。

每个有实质内容的单元至少应覆盖：

- **资料来源线索**：来自哪类资料或资料中的哪种内容，例如标题、表格、图、例题、公式、流程图、课堂强调点。
- **核心定义 / 结论**：保留资料中的关键表述和限定条件。
- **展开解释**：说明概念为什么提出、解决什么问题、内部过程或逻辑是什么。
- **资料细节保留**：保留资料中的分类、步骤、条件、优缺点、对比项、例子、图表信息、公式变量含义和适用范围。
- **考试化转换**：说明可能如何出选择、填空、简答、计算、分析、画图、证明、案例或综合题。
- **易错点**：指出学生容易混淆、漏写、算错或误用的地方。

如果资料中一个小节包含多个概念、图表、例题或算法步骤，不能合并成一句话带过，应拆成多个子点逐一讲清。

## 信息保留规则

讲义生成的目标是“复习资料化”，不是“删减摘要化”。处理资料时必须遵守：

1. 保留所有重要定义、公式、算法步骤、流程、分类、表格字段、图示含义、例题方法、实验步骤、案例要素和老师强调点。
2. 只压缩重复内容，不删除不同概念、不同条件、不同变形、不同例子或不同题型线索。
3. 对表格和图示要转写为文字说明或复习表，不要只说“如图所示”。
4. 对公式要说明变量含义、适用条件、常见题型和易错点。
5. 对算法、流程、实验、案例分析要保留步骤顺序和关键判断条件。
6. 对教材或 PPT 中出现的例子，要尽量保留为“例子/应用场景/题型原型”。
7. 如果某部分资料看不清、缺页或上下文不足，必须明确标注“资料不完整/信息不足”，不要凭空补全为上传资料内容。

## 扩写规则

不要只复述 PPT 的项目符号。对于每个重要概念，应解释：

- 为什么提出这个概念
- 它解决什么问题
- 它的工作过程是什么
- 它和相近概念有什么区别
- 资料中出现了哪些定义、图表、例题、公式、流程或强调点
- 考试中可能怎么问
- 答题时应该写哪些关键词、步骤或公式

## 资料标注规则

讲义中的关键内容应按来源标注：

- `来自上传资料`：直接从用户提供的材料中提取或改写。
- `基于资料推测的考点`：根据资料频次、标题层级、例题、作业题、往年题或强调痕迹推断。
- `补充背景知识`：资料中没有直接出现，但为了理解、解题或连接知识点需要补充。

不要大段堆积来源标签；可以在每个小节开头、表格列或重点块中标注。

## 质量检查清单

输出讲义前检查：

- [ ] 是否覆盖了用户上传或提到的每个章节、单元和主要小节。
- [ ] 是否遗漏了资料中的重要图、表、公式、例题、流程、算法、案例或作业题型。
- [ ] 是否存在“只讲常识、不贴资料”的泛泛段落。
- [ ] 是否有单元内容过短，无法支撑复习和做题。
- [ ] 是否把资料中的不同概念错误合并或过度压缩。
- [ ] 是否把补充背景知识明确标注出来。
- [ ] 是否给出了考试化表达、题型线索和易错点。

## 风格要求

内容要适合大学生期末突击复习。优先使用清晰标题、表格、例子、步骤化讲解、可直接背诵的表达和题型化提示。讲义应尽量保留资料的信息量，在结构上变得更清晰，而不是变得更空泛、更少。
